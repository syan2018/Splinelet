## 背景与要交付的改变

现有 Node 单测可统一运行，浏览器回归却只是签名不同的可注入模块，check:all 不包含它们。旧对象移动断言主要检查 path 位移，不能发现 V4 要解决的修改器中心漂移。需要先冻结可比较的行为，再用真实用户入口验收新模型。

每次分发都能给出可运行测试；简单体验、形状、输出属性、文件和原生能力均有独立证据，不把“旧测试绿”误当重构完成。

## 在整条管线中的位置

输入是原项目 fixtures、旧/新阶段结果与候选提交；输出是比较器、隔离 runner、基线 manifest、U/A 验收记录。

只写测试、最小 fixture 和证据；依赖安装与 package 脚本由 P00 整合。不得为通过测试而修改产品语义、放宽阈值或连接用户浏览器。

所有包共同守护：部件身份不依赖输出类型/数量；源定义是唯一权威，求值结果只读；普通用户的默认概念只有部件、线条、区域、颜色和厚度，高级业务按需展开。技术正确与默认体验同时验收。

## T01 的 runner 执行协议

这是实施合同，当前命令尚不存在。P00 先登记 Playwright 版本、浏览器二进制安装命令、`package.json`/锁文件唯一写者和接口提交；P01 随后只改 runner、case/fixture 和报告范围。

- 参数固定 `--suite legacy|v4`、`--case <清单中的名称>`（省略跑整套）、`--target web|desktop-frontend`；未知参数、未知 case、没有用例、超时、端口冲突或断言失败必须非零退出。报告记录全清单，通过/失败/未执行分列；必需项 skip 不得判整套通过。
- Web：预先完成 `pnpm build`，runner 使用本次 `dist/server/wrangler.json` 启动 `pnpm exec wrangler dev --config dist/server/wrangler.json --local --ip 127.0.0.1 --port <测试端口> --inspector-port <隔离调试端口> --persist-to <本次输出目录>`，固定本地模式；记录构建与配置 hash。不得退回 dev 源码服务。
- 桌面前端：预先完成 `pnpm desktop:build`，runner 自管 Node 静态服务，根目录严格为 `src-tauri/target/frontend/`，正确服务 JS/WASM/MIME 和入口；不能读取工作区其他目录。这里验证共用前端，不声称运行了 Tauri IPC。
- 测试端口和 inspector 端口必须是 runner 专用空闲端口；启动失败或服务自行换端口即失败。每例创建新 context 与 fixture，文件句柄/OPFS 内容均来自该隔离上下文，禁止连接用户 CDP 或页面。
- `finally` 关闭 context、浏览器和本次子进程；只处理记录的 PID/已核对绝对路径，不能根据端口杀未知进程。Windows 后台服务按仓库/工具约定隐藏启动。
- 清单至少注册 `basic-authoring`、`object-move`、`progressive-workspace`、`repeated-motif`、`reference-space`、`failure-repair-reopen`、`saving-recovery`、`api-parity`，分别由 P07/P02/P06 交付。用例尚未实现时明确未执行，不生成占位 PASS。
- `repeated-motif` 覆盖 U04，`reference-space` 覆盖 U05，`failure-repair-reopen` 覆盖 U06；每例从正常入口运行，验证默认未要求技术设置、高级展开不改定义。T01 先完成可运行的 legacy suite，V4 清单随交付逐项启用，最终全套不得缺项。

验收时记录 runner 合同版本、实际启动参数、进程/端口归属、case 清单及错误退出测试结果。
