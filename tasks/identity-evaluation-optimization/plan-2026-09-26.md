## 本次交付边界

完成兼容现有 V4 文件的身份运行时优化：统一完整身份规则，避免比较时重复序列化大字符串，对区域、赋值和继承候选建立索引，并在一次求值/视图投影内复用查询上下文。保留原 key、lineage、instances、区域绑定与 UI 布局交互。

此次不将短路比较视作全部交付。必须覆盖精确引用解析、selected scope、外观/浮雕/制造查询、分裂合并继承，以及真实样例的完整求值等价性。

来源 DAG 与紧凑持久化标识需要文件迁移、复制重映射及输出契约版本设计，本次保留评估结论，不在性能补丁中改变存储协议。求值图裁剪、跨请求增量缓存及请求取消属于独立行为边界；本任务不混入这些变化。

## 正确性约束

- 完整身份仍由 ownerNodeId、operatorId、port、key、instances、lineage 决定；不使用坐标、面积、数组下标或每次求值生成的随机 ID。
- 保留既有稳定序列化结果；对象属性顺序不影响身份，实例/lineage 数组顺序保持现有语义。
- 相同完整身份的多个区域或多个赋值不得被 Map 覆盖；歧义和冲突仍由原消费者报告。
- selected 空集保持空；失效 selected 阻断，不回退到 all。
- 继承仍是提案；精确匹配优先，跨 owner/instances 不继承，多个父赋值不一致时报告冲突；输出顺序和诊断顺序保持一致。
- 可变命令草案、撤销/重做、preview 和换文件不能读取过期缓存。查询索引限定一次同步操作/不可变快照，不给任意可变引用增加长期全局缓存。
- 不在持久化 DTO 或 Worker payload 内附加不可序列化的缓存对象。

## 评估方案

1. 基线与优化使用同一输入、同一 Node 版本、相同 requestedDomains，预热后至少测量三次，记录每次原始耗时和中位数。
2. 对真实 Sandrone 的原样例、颜色、厚度、刚性变换和源编辑场景保存完整求值与创作视图摘要；比较不得仅看区域数或截图。
3. 单独覆盖重复区域/赋值、失效引用、数组顺序、复制后的实例、split/merge、空 selected、输入不变性及可变草案，使用旧算法作差分参照。
4. 性能测试不设易抖动的绝对毫秒 CI 门槛；报告求值与投影的变化。算法测试验证索引复用和候选正确性，不把机器速度当正确性。
5. 浏览器只使用新 context、非用户端口和 fixture；核对原 UI 编辑、颜色/高度和撤销后的结果，记录“正在更新区域”对应链路的实际时间。Node 时长与浏览器时长分别报告。
6. 交付前执行 typecheck、lint、test、format:check、build、desktop:build、desktop:format:check、desktop:check，并按改动执行 core/export 与相关浏览器回归。已知全库格式问题单独报告，不批量改无关文件。
