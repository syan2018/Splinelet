# 3MF 打印导出

默认打印按钮导出 `.3mf`；原 `stl` API 留作兼容。3MF 文件保存毫米单位、材料名称与显示颜色、独立色块实体、部件/区域名称、相对位置，以及工程的打印层高和堆叠层元数据。导出整个装配作为一个 build item，各色块作为组件，避免导入后各层分别被放到平台上。

这是通用模型文件，不是某款打印机的切片工程。材料的显示颜色不等于打印机耗材槽：用户在切片软件中为色块指定耗材，并设置切片层高。依据 [3MF Core Specification](https://github.com/3MFConsortium/spec_core/blob/master/3MF%20Core%20Specification.md) 的 base materials、components 和 OPC 包结构实现。

## 几何链路

导出调用现有 `compileCreation → buildSolid`，所有实时轮廓、修改器、分层、切削和制造清理都来自同一链路。为分色导出增加以下末端处理：

1. 对每个凸起实体应用相同的切削。
2. 在各个实际高度区间内，按顶面高低和预览中相同高度的覆盖顺序划分二维截面，再拉伸成互不重叠的分色体积。相邻且截面相同的区间合并。只消除重复占据的空间，不修改源工程。
3. 分别检查各色块的闭合性，核对各色块体积之和与整体实体体积。
4. 将独立实体与材料引用写入标准 3MF ZIP，保留原位置。无效分色实体会停止导出，不会退回一个丢色的整体网格。

`lib/three-mf.mjs` 负责格式与资源引用，`material-solids` 负责分色截面，`solid-engine` 负责实体，worker 完成计算与打包，`manufacturing-download` 负责浏览器下载/API base64。API 返回 `filename`、`mimeType`、`base64`、`materials`、`parts`、`report`，不自动下载。

3MF 可以表达多个分离实体，导出不再强制“只能有一个连通体”。实体检查仍显示分离数量，供用户决定是否需要连成一体。

## 承托部件的定位

原“底板”入口收为默认折叠的「生成承托部件 · 可选」。它只是创建一个引用其他部件外形、合并、外扩的普通修改器对象，再放入已有的通用分层体系。已有完整底层轮廓时不需要额外生成。

## 有限验证范围

检查：两种相交材料分成互不重复的体积；穿孔同时作用于分色实体；包内关系、资源 ID、中文与 XML 转义、毫米单位、单个装配及颜色引用；真实工程导出；浏览器下载后解包；生产构建。对照官方核心 XML schema 验证。实际打印机耗材映射与切片参数由切片软件处理，本应用不伪造机器配置。

已验证真实分层试验工程：69 个色块、5 种材料，350083 字节，整体闭合且为 1 个连通体。浏览器下载也得到 69 个独立网格和 5 个材料引用，官方 XSD 校验通过；页面无脚本异常，1440×1000 视口无页面溢出。TypeScript、生产构建、新导出检查和打印分层回归通过。未声称已在特定切片软件或实体打印机上完成验证。

复现命令：`node scripts/test-3mf.mjs`；`python scripts/validate-3mf.py 文件.3mf`。后者使用 `lxml` 与 `xmlschema`，从官方仓库缓存核心 XSD；若放入隔离目录，依赖位置为工作区 `outputs/3mf/validation-deps`。
