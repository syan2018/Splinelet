# 区域作者模型与求值职责

日期：2026-09-26。状态：第一性复审后的设计方向，尚未完成实现与验收。本文撤回“V5 边界选择器已经解决根因”的结论；该实验保留在[历史设计](../qa/region-selector-experiment-2026-09-26.md)，证据见[实验记录](../qa/region-repair-2026-09-26.md)。工作区已有实验代码不代表本设计已经落地。

## 要解决的问题

用户需要编辑可着色、可设置厚度、可参与构造和制造的区域。源曲线变形时，这些创作对象及其设置必须有明确的归属；保存、撤销和重新求值必须重现同一个作者状态。

“每次求值产生的面都要有稳定身份”不是独立的产品需求。现有实现先用路径重建平面分区，再让颜色、厚度、构造输入等依附派生面，因此制造了每次重算后找回旧面的任务。V5 将几何匹配换成有序边界选择器，改善了拒绝错配的能力，但仍然要求作者设置依附于“本次分区中恰好满足条件的一面”。这个前提没有改变。

“区域数不变”“找不到就暂停”“保留旧定义”均不足以证明产品正确。必须先回答哪个用户动作有权改变区域对象，以及普通形状编辑为什么会被当作区域对象的重新创建。

## 当前引用混合了不同职责

| 使用处                     | 用户实际意图               | 应持久化的对象                              |
| -------------------------- | -------------------------- | ------------------------------------------- |
| 悬停、点击、框选、候选预览 | 操作当前显示的内容         | 不持久化；句柄只在对应修订有效              |
| 部件默认颜色、默认厚度     | 整个部件的属性             | 作者部件                                    |
| 局部着色、局部厚度与放置   | 可编辑的表面/浮雕对象      | 作者区域及其表面处理/浮雕特征               |
| 布尔、偏移、阵列的输入     | 明确的构造操作数           | 作者区域、构造对象、声明的结果集合或实例    |
| 独立处理程序结果的一个碎片 | 将该局部范围用于后续操作   | 显式局部构造/转换；或用户明确选择的动态查询 |
| 名称、制造 Part、打印排除  | 对创作对象的组织和生产设置 | 作者对象或特征                              |

代码证据：`creation-intents.mjs` 将选中 cell 转成 paint/relief 的 OutputRef；`output-queries.mjs` 将外观、浮雕、展示和制造统一按 OutputRef 查找；`resolveRegionScope` 要求选中的输出恰好解析到一个面；`bindReferencedRegions` 将临时 cell 转成持久选择器。`paint-region` 首次上色还会同时创建局部 relief，使外观编辑与制造实体创建耦合。

## 方向：作者对象与程序式结果分层

采用两类明确的作者输入：可编辑区域的共享边界拓扑，以及程序式构造特征。属性与消费者引用这些作者对象。计算所得 polygon、连通组件、三角形只属于结果层。

### 可编辑区域

保存共享接点、边界曲线、区域的有向边界环和属性。曲线几何只保存一份；相邻区域引用同一条边界。区域记录连接关系及绕行方式，不另存一份可独立修改的采样 polygon。

前一版把“作者面”直接等同于“双份几何权威”是不成立的。边界引用与派生网格属于不同层。已有 Sketch 顶点、边、Path 可以复用，但必须明确曲线内部控制点与拓扑接点的不同职责。

普通编辑保持作者连接关系。曲线穿过另一条曲线不自动焊接；轮廓重叠不自动合并创作对象。切分、焊接、分离、合并区域是明确的作者操作，在同一可撤销事务内改变拓扑和属性归属。自动求交可帮助这些操作生成候选，不能在每次拖点后重新决定作者对象有哪些。

共享边界的向量拓扑模型提供了参考：VGC 原始论文区分曲线几何与作者拓扑，说明重新计算平面图为何会丢失面属性，并提供显式连接、切分等编辑操作。本项目只评估所需的共享边界与有向环，不引入完整动画或非定向曲面模型。[Vector Graphics Complexes](https://www.borisdalstein.com/research/vgc/vgc.pdf)

### 程序式构造

布尔、偏移、描边、阵列等继续保留参数化求值，结果属于构造特征。下游可以引用整个声明结果或明确的实例；一个结果允许为空或包含多个连通组件，不因组件数量变化而创建或删除作者对象。

对单个结果碎片进行独立编辑，必须表达额外意图：建立可编辑区域、增加明确裁剪构造，或者显式使用动态子区域查询。最后一种确实存在拓扑寻址问题，应有可见的查询含义、失效和重选入口，不能作为普通涂色/厚度操作的隐藏默认机制。

“把生成结果转为可编辑区域”若解除参数联动，必须明确说明。历史 Path 的独立移动、自动交点和程序式关系不能无条件批量转为共享接点；迁移必须保留其原语义，或提供明确的转换结果。这是模型变更，不是重命名几个字段。

### 数据流

```text
共享源几何 + 作者区域边界环 + 表面/浮雕特征
                       或
                程序式构造特征
                        ↓ 只读求值
            当前轮廓 / RegionSet（可多组件）
                        ↓ 明确的覆盖、裁剪和制造规则
            分色截面 → 实体 → 网格 / 3MF
```

作者区域与求值 polygon 不要求一一对应。指定边界与填充规则决定当前几何范围；属性属于作者对象。SVG 填充也从指定路径计算内部，而非先要求计算后的各组件拥有持久身份。[SVG 2 填充规范](https://www.w3.org/TR/SVG2/painting.html#FillProperties)

## 编辑语义

| 操作                    | 作者状态改变       | 必须成立的规则                                           |
| ----------------------- | ------------------ | -------------------------------------------------------- |
| 拖动内部控制点/控制柄   | 曲线几何           | 不重建全部作者区域，不迁移属性                           |
| 精确拆分贝塞尔段        | 曲线内部表示       | 区域仍引用同一边界曲线；几何不变                         |
| 删除普通控制点并拟合    | 曲线内部表示及形状 | 共享该边界的区域同时更新，不按新 polygon 分配属性        |
| 反转显示/遍历方向       | 表示及有向引用     | 不改变区域内外语义                                       |
| 移动共享接点            | 接点及相邻边几何   | 相接边仍共享同一个端点                                   |
| 删除多区域共享的接点/边 | 明确的拓扑操作     | 不能伪装成普通控制点删除，必须处理受影响连接与对象       |
| 切分作者区域            | 新边界及子区域     | 本次命令明确产生父子关系，按声明政策复制设置             |
| 合并作者区域            | 新区域及被替代对象 | 不同材料/厚度/放置不能由几何算法选赢家；需要明确合并策略 |
| 删除区域/构造对象       | 删除作者实体       | 同一事务处理消费者或保留可定位的失效引用                 |

数据层要分开形状编辑与拓扑操作。现有“端点动态找边并延长”对于作者区域应转成明确连接；若保留为程序式功能，它改变的是该特征结果，不能偷偷修改作者区域的连接关系。

颜色与厚度也要拆开。给对象上色不应隐式新增一个必须稳定寻址的独立制造实体；是否启用浮雕、采用什么默认厚度，应由明确的产品规则负责。

## 身份仍有用途，但不需要猜出来

作者实体保留普通 ID，用于引用、保存和撤销。对象的存在由作者命令决定，读取文档即可知道，无需从新几何中辨认。

派生 cell、布尔碎片、三角形使用一次求值内的句柄。点击经当前快照的来源信息定位作者对象；若当前碎片没有独立作者对象，操作不能默默赋予它跨任意重算的身份。句柄过期影响当前选择或该次操作，不要求整个工程重新对齐。

来源信息继续用于命中、诊断、显式切分和一次性迁移验证。面签名、面积重叠、参数域匹配不再承担默认作者属性归属。确实需要高级子形状寻址的功能单独承担其限制；OCCT 拓扑命名中的生成、修改、删除及分裂/合并记录属于这一类专门问题。[OCCT 拓扑演化](https://dev.opencascade.org/doc/refman/html/_t_naming___evolution_8hxx.html)

## 头发反例的验收含义

删除曲线内部控制点，不应删除头发的作者区域再尝试认回颜色。它改变共享边界的形状。若产生自交、重叠或不可制造结果，应报告具体几何/制造问题，而非一批不透明的身份丢失。

实验中一次点移动使自动平面分区由 12 面变成 11 面，只证明派生图变化；不能据此认定用户请求了两个作者区域合并。此前将这一现象直接作为属性失效的充分理由，缺少作者意图这一前提。

不得通过挑选不触发问题的节点、减小拖动幅度或固定区域数量绕开反例。必须保留原失败操作，检查属性实际归属、共享边界、构造关系和制造结果。

## 性能问题独立修复

pointer move 的源反馈只依赖源几何，不应执行区域、浮雕或实体求值，也不应发布整工程预览。提交后按实际依赖调度后台计算，结果按修订隔离，下一次源编辑无需等待。

已经定位的 React 渲染同步求值、requestedDomains 只过滤输出、拖动复制整文档、消息重复克隆等修复可以保留。它们不能证明旧身份需求正确，也不能代替作者模型清理。当前测量未证明所有设备达到 60 fps。

## 落地顺序与发布门禁

1. 冻结扩充面匹配/选择器的工作，保留实验和失败证据，撤回“V5 已完整修复”的状态。
2. 先完成共享边界的最小端到端切片：两个不同颜色/厚度区域，覆盖删内部控制点、反转、穿越、显式切分、合并冲突、保存和撤销。直接检查属性范围与边界，不检查计算面编号。
3. 将外观、浮雕、构造输入、制造范围和临时选区分别迁移到正确的目标类型，不能保留统一 OutputRef 再隐含依赖当前 cell。
4. 旧文件转换只在副本执行。验证曲线、填充、属性、制造等价，列明增加的接点、解除的参数联动及编辑语义变化。不能把所有隐式交点直接升级成作者接点后声称无损。
5. 用原始与用户编辑后的头发工程执行原失败操作。保持现有页面布局和源编辑入口，验证新增拓扑能力不会使样条编辑变得不可用；缺少表达能力必须先补齐。
6. 默认路径脱离面身份对齐后清理旧契约及不再使用的兼容链，执行双端构建、全部仓库门禁与真实交互测量。

当前第 2–6 项尚未通过。已有实验不作为完整修复交付。保留的基础是共享源几何、原子事务、只读求值、依赖缓存和即时源反馈；需要撤出的基础是把临时平面分区作为全部作者设置的寻址空间。
