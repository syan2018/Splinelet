# 修改器链、输出快照与断链修复

日期：2026-09-26。状态：修正方案，逐项实现和验收中。此前把 V5 边界选择器作为根本修复的判断已撤回；将共享边界作者区域作为统一替代模型的方向也收窄为一种可选输入。工作区实验代码不代表本文已经完整落地。原实验见[历史设计](../qa/region-selector-experiment-2026-09-26.md)和[失败证据](../qa/region-repair-2026-09-26.md)。

## 第一性：保存操作意图，计算它的结果

用户需要的是：曲线改变后，构面、裁剪、着色、厚度和制造处理按照自己建立的关系继续工作；关系不能成立时，可以知道哪里出了问题、检查此前结果并修复该关系。

每次求值产生的面都拥有跨任意拓扑变化的稳定身份，不是需求。需要稳定的是作者建立的修改器、输入关系、声明的结果用途和显式实例。polygon、连通组件和三角形是计算结果，不反过来决定作者对象的存在。

统一采用现有 Program/Operator 依赖图。界面可以呈现为修改器链，实际结构允许分叉和汇合。共享边界模型若有必要，作为源修改器的一种输入；不能形成第二条独立的属性、求值和持久化管线，也不批量焊接旧工程的隐式交点。

## 必须分开的三种情况

| 情况     | 判断依据                                                  | 处理                                                                  |
| -------- | --------------------------------------------------------- | --------------------------------------------------------------------- |
| 普通更新 | 输入引用和声明语义仍成立，源几何或参数改变                | 标记受影响节点，按依赖顺序增量求值；不重建作者关系                    |
| 断链     | 生产者/输出端口消失、域不兼容、明确子选择无法满足或有歧义 | 保留断开的引用和原因，暂停依赖该输入的节点，进入修复流程              |
| 计算失败 | 引用仍有效，但参数、几何或内核计算失败                    | 定位失败步骤，允许改参数/源数据、合法旁路或移除；不以自动重绑掩盖失败 |

合法的空结果是一种成功结果。多连通组件也不自动等于断链。是否要求单个对象由消费者的显式契约决定。拓扑变化本身不能触发全工程身份重建。

这里的“只有断链才重建”指重建作者关联。上游形状改变后，受影响的布尔、网格等仍需重新计算；不能因为有旧快照就认为计算结果仍然有效。

## 唯一作者权威和三类输出

文档只保存源数据、修改器及参数、显式输入引用、作者属性和组织设置。求值只读文档，不改引用、不分配作者身份、不迁移属性。

1. 整体结果：引用 owner/operator/output port 或具名结果角色。一个结果可包含零个或多个连通组件，消费者按集合处理。
2. 显式实例：引用创建实例的修改器及作者可见的 occurrence。实例序号只在该修改器声明的规则内有意义；减少数量造成实例消失时不能自动跳到相邻实例。
3. 子选择：若用户确实只要结果的一部分，建立可见的选择/裁剪修改器。它保存输入、选择含义、锚定条件、基数和失效策略；颜色、厚度等下游引用这一步的输出。禁止在一次上色后偷偷建立全局 cell 匹配系统。

临时点击句柄只在对应求值版本内有效，用来源信息定位上述作者目标。面积、质心、polygon 下标和内容 hash 不成为持久作者引用。hash 可以用于缓存，来源信息可以用于诊断和明确的求解。

## 应进入链条的行为

| 当前职责/行为                              | 目标修改器职责                                                | 更新及失败范围                                   |
| ------------------------------------------ | ------------------------------------------------------------- | ------------------------------------------------ |
| 源 Path、共享边界、外部引用                | Source / Reference                                            | 几何变化使依赖该输出的分支失效                   |
| 动态端点延长、接合、闭合                   | Join / Extend / Close                                         | 明确输入与连接约束；无法满足时定位该步           |
| 填充、分区、选局部、布尔、描边、偏移、阵列 | Fill / Partition / Select / Boolean / Stroke / Offset / Array | 输出明确集合或实例；子选择单独承担歧义           |
| 局部颜色和表面覆盖                         | Appearance / Surface treatment                                | 引用前一步作用范围；上色不隐式创建制造实体       |
| 厚度、浮雕启用、层叠和相对放置             | Relief / Placement                                            | 独立参数、输入和状态，制造依赖清楚可见           |
| 合并、裁切、制造清理和网格化               | Body / Cleanup / Mesh                                         | 作为明确可检查的处理步骤，不静默改用户源线       |
| 固化当前结果                               | Snapshot source / Bake                                        | 用户显式创建固定输入，保留来源说明并解除实时依赖 |

不是所有状态都要伪装成修改器。控制点是源数据；选择、撤销、作业队列、缓存和全局单位是编辑器或运行时职责。实现可复用现有纯几何函数，通过注册的节点适配器调用，不复制内核。

当前代码只把 curves/regions 纳入注册图；evaluate-document.mjs 仍固定串联 relief、placement、body 和 cleanup。后续逐步把这些作者可配置行为纳入同一类型化计划，保留现有算法、UI 与端口适配；过渡适配层不能长期成为第二套依赖系统。

## 快照契约

每个节点的每个输出端口有不可变 StageResult，携带文档 epoch/revision/preview version、直接输入版本和诊断。缓存键由该节点、声明依赖及上游版本产生；不能靠全工程几何匹配判断是否复用。

运行时分别管理：

- 当前状态：pending/running/ready/empty/failed/needs-binding/blocked-by-upstream，区分直接失败和依赖失败。
- 最近一次已提交成功快照：每端口至多一份，用于查看、对比和修复。预览、失败和过期 Worker 响应不覆盖它；换工程清空，删除节点释放。partial domain 请求不能误删未请求的端口。
- 显式固定快照：用户用 Bake 创建的新作者输入，作为资源随文件保存、可撤销。它与只用于显示的缓存不是一回事。

显示旧快照必须标明版本和过期状态。它不能被暗中作为新求值、命中选区、吸附、属性赋值、制造或导出的当前输入。当前合法 empty 应清除此前图形，不能继续显示旧几何冒充成功。

快照缓存丢失只影响性能和历史查看，不影响文档冷求值。若以后持久化可丢弃缓存，必须校验格式、算法版本、依赖指纹和资源内容；不能将其升级为第二份可编辑权威。

## 断链修复协议

求值报告结构化问题：消费者 owner/operator/input port/index、原引用、直接生产者、原因和受影响下游。不要把同一根因复制成几十条“区域失效”。

关联继续成立时按明确关系更新。确需修复时，候选可从具名结果角色、源路径/边界、实例关系、作者接合约束和已声明选择条件中求解。几何相似性只能作为有说明的建议证据，不能自动替用户决定属性归属。无法唯一确定则等待手动选择，不全局猜测。

修复界面基于现有修改器卡片提供：

1. 定位断开的输入及其源对象，查看当前结果、上次成功快照和原因。
2. 编辑源数据/参数、恢复上游；类型允许时旁路，或按明确结构操作移除此步。
3. 重新指定输入或修改选择条件：先在候选文档中求值，展示改动、直接影响的下游和仍存在的问题。
4. 用户提交后，以捕获的 epoch/revision 原子更新关系，一次撤销可恢复；取消不改文档。预览期间工程改变，候选失效，不能抢写新状态。
5. 必要时显式固化旧快照并改接到它，或保留断链继续编辑其他部分。

第一批实现处理现有具名输入端口的明确替换。复杂子选择必须通过它自己的修改器契约修复，不能用“重绑端口”偷偷清空 scope 或改成 all。修复提交只更新用户选定的关系，不自动重写所有下游参数。新类型、环路、owner/frame 和引用完整性必须验证；几何仍失败可继续显示诊断，不能要求整个工程先成功才允许修复一个局部关系。

## 交互和故障隔离

源曲线反馈仅依赖源几何；pointer move 不跑区域、浮雕或实体求值。提交后后台更新真实依赖闭包。源编辑、保存、撤销和基于当前作者 ID 的参数修改不等待全部区域 ready。只有依赖当前派生结果的操作才等待对应结果。

节点失败只暂停真正的消费者。独立分支继续计算和显示，修改器卡片保留当前参数与修复入口。计算排队、过期显示、断链、参数错误与内核异常不能合并成一个阻塞全局的“正在更新区域”。

导出要求请求范围的依赖闭包在同一当前版本全部成功。完整工程导出不得混用新旧结果或静默跳过失败分支。显式选择独立部件导出时可以只校验该范围，但必须明确范围。

## 复用基础与清理顺序

现有 Program/PortRef、buildDependencyGraph、evaluateConstruction.components、依赖缓存、EditorSession 原子 prepare/commit/undo 可以保留。StageResult 已有 ready/empty/absent/blocked；逐步加结构化原因和运行时视图，不把展示状态倒写文档。当前 cache 只存最新结果，并不是可查看的最后成功历史。

1. 先交付链状态、逐端口成功快照与明确输入修复切片，解除不依赖几何的修改器编辑锁；保留 exact revision guard。
2. 将隐式连接与局部寻址改为显式 Join/Select 等节点，优先处理头发例中的分区和局部属性；旧 V5 选择器只能作为迁移材料，不能继续扩张成默认作者模型。
3. 将 Appearance、Relief、Placement、Cleanup 纳入同一类型化依赖计划。新旧适配结果对照通过后逐段删除固定编排与重复寻址。
4. 旧文件仅在副本迁移；保持源曲线、明确参数联动和初始物理结果。无法无损表达的关联形成可定位的待修复项，不自动焊接交点或固化程序结果。
5. 重放原头发失败操作，验证属性范围、链状态、可修复性、撤销重开和制造结果；不能另选安全节点或缩小位移绕过反例。
6. 清理被替代的契约和硬编码规则，完成仓库检查、双端构建、隔离浏览器交互测量，再替换公开示例。

验收不是“面数不变”或“静态 3MF 可打开”。必须证明普通编辑无需重建关系；真实断链可定位、可修复、可撤销；无关分支和源编辑持续可用；旧快照不会被误用；原失败工程能够按明确语义完成编辑与导出。
