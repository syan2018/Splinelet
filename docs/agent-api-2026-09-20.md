# Agent API 5

原 Web/Tauri 工作台的 `window.traceStudio.version` 为 `5.0`。`window.traceStudio.call(action, args)`、WebMCP 和开发用本机 HTTP 桥进入同一个 Studio host；GUI、Agent、预览与撤销共用一个 editor session。当前新建与原生文件使用 V5；`capabilities.get` 和 `document.get` 的 documentVersion 均报告当前文档版本。求值使用同一规范求值器与 Worker，返回结果携带 epoch/revision。

V5 区域 OutputRef 的 key 是声明式 RegionDefinition ID，lineage 为空；字段结构与 API 动作保持兼容。查询返回的临时 `cell:` 句柄只能用于当前修订的显式作者命令，绑定后应重新读取稳定引用，不应缓存临时句柄跨修订使用。旧工程通过验证迁移后另存，转换失败不会替换当前工程。

## 读取、写入与单位

先调用 `capabilities.get` 发现当前 host 实际注入的动作，再用 `document.get` 读取规范文档和修订。工具名、输入 schema、只读标记和兼容写入的 revision 门禁来自同一公开注册表；未注入的选择、求值或导出能力不会在 capabilities 中宣称可用。API 5 作者动作使用稳定 Node/Path/Vertex/EdgeEnd/OutputRef，毫米与弧度；`draw-path` 的 points/cubics 是世界毫米坐标，存入所属 Shape 的局部 Sketch。镜像/阵列 center 是 Shape 局部坐标或参数引用；对象移动只改变 pose。

```js
const call = window.traceStudio.call;
const read = await call('document.get');
const changed = await call('authoring.run', {
  expectedRevision: read.revision,
  action: { kind: 'create-shape', name: '纹样' },
});
const shapeId = changed.lastChange.selectionIntent.activeRef.id;
const drawn = await call('authoring.run', {
  expectedRevision: changed.revision,
  action: {
    kind: 'draw-path',
    ownerNodeId: shapeId,
    closed: false,
    points: [
      [0, 10],
      [4, 4],
    ],
    cubics: [
      [
        [0, 10],
        [2, 9],
        [5, 6],
        [4, 4],
      ],
    ],
  },
});
await call('undo', { expectedRevision: drawn.revision });
```

不能在提交时悄悄把旧修订替换成当前修订。过期写入失败，需重新读取并评估原操作。`preview.begin/update/commit/cancel` 同样携带 expectedRevision 和对应 previewId；一个提交是一条撤销记录。`selection.get` 读取原工作区的稳定选区，Group 以 node 引用返回。

## 重复纹样

规范命令有 `mirror-curves`、`repeat-curves`、`connect-boundaries`、`fill-curves`。它们显式消费已发布曲线，添加新的曲线端口；新 Fill 显式发布 regions。已有 Fill 前的线性插入使用 `add-program-modifier`，可用性由 `creation_inspect` 的 modifierAdd/structure 给出。不要隐式重接任意分叉。

`repeat-pattern` 将镜像、阵列、Join 和 Fill 作为一次事务建立。连接端点为 `{edgeEnd, mirrorIndex, index, wrap}`，edgeEnd 通过 sketchId/edgeId/end 指定；index 可用整数或 `each/next/previous`，wrap 决定首尾循环。生成的算子 ID 由命令分配。Join 保存端点实例对应，Fill 使用这些拓扑关系；近似重合的两个独立端点不会自动变成连接，Join 的距离校验仍使用工程容差。

完整可执行样例：[draw-cup-emblem.mjs](../scripts/examples/draw-cup-emblem.mjs)。它只在实例工程副本上建立开放源线、镜像四向重复、显式邻接和五个孔；原源线保持可编辑，中心/轴随 pose 移动。样例绘图结果是验收数据，不替换用户的图样。

## 求值、存储与导出

`evaluation.request` 接收 `{epoch, revision, domains}`，domains 可包含 curves、regions、relief、placed-relief、bodies。结果中的 blocked 聚合没有可导出的 value；relief/placedRelief 的 branches 保留本次求值中独立有效的部件。预览读取 branches，完整实体导出读取聚合，详见[构造链](architecture/construction-pipeline.md)。

`export.run` 接收 `{epoch, revision, format, stage, options?}`，使用已提交结果，返回 artifact。浏览器 JS 的二进制 artifact.data 为 ArrayBuffer/typed array；WebMCP/HTTP 将二进制显式编码为 `{encoding:'base64', type, byteLength, base64}`。不要将 JSON 序列化后的空对象当成文件。

保存完整工程继续调用 `export({format:'json'})`，返回包含资源的 `.spl` base64；文件打开入口或 `load_project({expectedRevision,base64})` 可重开。`export.run` 输出制造文件，不代替工程保存。

## 兼容入口

原 `state/creation_inspect/spline_inspect`、选择与视图入口继续保留。原源编辑、创作命令、高级模型写入和 load_project 必须额外提供 document.get 读到的 expectedRevision。`creation_command` 的 paint/height 还保留其显示区域 revision 校验。兼容坐标仍由各旧命令定义；新脚本优先使用上面的规范命令。

`manage_group` 整理的是路径 Collection。场景 Group 使用 group-nodes/ungroup-nodes/reparent-nodes，后者默认保留世界位置；Group 不拥有颜色、厚度或构造程序。`legacy.read` 只返回稳定引用投影。
